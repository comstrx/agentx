# Orchestration

Driving child processes — the infra-tool's core competence: spawn, supervise, and kill without leaving a mess.

- **Every child gets its own process group** (`setpgid`/`process_group(0)` at spawn): signals target the GROUP (`killpg`), so a child that spawned grandchildren dies as a family — killing only the direct pid is how orphaned workers survive to corrupt the next run.
- **The kill ladder is graceful then final:** SIGTERM to the group → bounded poll for real death (seconds, not hope) → SIGKILL escalation → reap (`wait`) so no zombie rows outlive the tool — the ladder is ONE shared primitive every stop/clear/restart path calls; per-call-site kill logic drifts into leak bugs.
- **Output streams are drained, bounded, and never deadlock:** reader threads (or async tasks) consume stdout/stderr from spawn — a full pipe blocks the child silently; stderr capture is size-capped char-safe; after kill, drain with a grace timeout instead of an unbounded join (a setsid-escaped grandchild holding the pipe must not hang the tool forever).
- **Liveness is checked honestly:** signal-0 probes existence; pid-reuse is guarded by group membership (a recycled pid that no longer leads our group is DEAD to us) — and the tool never kills a pid it cannot prove it owns; the registry of spawned pids is state, swept on start against reality.
- **Detached background mode is a first-class spawn path:** double-detach (sessionless, fds to the log sink, cwd sane), the pid + log + control paths printed to the user, the foreground `status`/`watch` able to adopt and render the background run — background is the same run with a different terminal story, never a second implementation.
- **Signal handling is symmetric:** the tool guards its own SIGINT/SIGTERM (finish the critical write, kill the children, release the lock, restore the terminal, THEN exit) — and children spawned BEFORE the guard installs don't inherit a blocked mask that breaks their own handling; Ctrl+C during any operation leaves the same valid world a clean exit does.
- **Timeouts wrap every child interaction:** spawn-to-ready handshakes, per-turn work budgets, drain grace — each a named const; a hung child is a diagnosable timeout with the child's tail shown, never a frozen tool the user must `kill -9` (becoming the orphan-maker it was supposed to prevent).
- **The child's environment is constructed, not inherited blindly:** cwd explicit, env passed deliberately (the tool's own noise stripped, the child's needs provided), stdin closed or piped by decision — "works when I run it by hand" bugs live in accidental inheritance.
- **Exit codes are read as protocol:** the child's code maps to the tool's vocabulary (success, retryable, broken-tool 126/127 distinguished from failed-work) — 126/127 is an environment problem reported as such immediately, never burned through retry budgets.
- Prove it with kill tests: spawn → kill the tool mid-run → assert no surviving group members, no zombies, lock recoverable, state valid; plus the pty smoke for signal-during-interactive — orchestration bugs are exactly the ones unit tests miss and users meet.
