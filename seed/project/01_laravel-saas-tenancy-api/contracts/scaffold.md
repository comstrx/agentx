# Scaffold

`context/` — the platform's identity as declared data; the per-client edit surface of a fork.

- **`config/` says how the framework behaves; `context/` says WHO the platform is:** panels/domains, the permission genome, gateway defaults, provider port bindings, dns credentials, the first-admin bootstrap — one file per concern under `context/*.php`, merged by a service provider into `config('context.*')`, and **`config:cache`-safe**: the merge skips when configuration is cached so the cached snapshot (with `env()` already resolved) wins and nothing reads `env()` at runtime.
- **In a client fork, `context/` is what changes:** business code, the engine, and migrations stay identical across forks; a fork whose diff leaks outside `context/` (plus the client-facing surfaces) is a fork rotting into a branch.
- **The permission genome is formulas, not rows:** a Scaffold DSL authors entities — `quads(resources)` (the view/add/edit/delete lifecycle), `verbs([...], resources)` (partial lifecycles), `allow(abilities)` (the `allow_*` switches), `grant(names, default:)` (raw grants), `minus(names)` (named subtractions) — with shared sets declared once and reused across panels (`delivery ≡ affiliate ≡ $cores`). A new resource is one entry in one `quads()` list; five hundred hand-typed permission rows is the drift the DSL exists to kill.
- **Expansion parity is machine-checked:** the DSL expands to the exact `entity => [[name, default], …]` contract the `permission:sync` / `permission:verify` pair consumes — genome-vs-database drift is a red verify in CI, never a mystery 403 in production.
- **Ports bind here, credentials live as data:** `context/ports.php` maps each Support port to its driver by env (identity, underwriting, provider, message, client, cache); tenant-scoped credentials (gateways, providers — keys, margins, webhook secrets) seed FROM context but LIVE in their tables, encrypted — binding is config, credentials are rows.
- **Seeding consumes context, never literals:** tenant provisioning, super-admin bootstrap, gateway/provider rows, platform defaults all read `config('context.*')` — a seeder with an inline credential or panel name has forked the platform's identity into code.
- The bar: onboarding a new client = edit `context/` + brand surfaces, run sync + verify green — measured in hours; the first client that requires touching a service file has named an abstraction the core is missing.
