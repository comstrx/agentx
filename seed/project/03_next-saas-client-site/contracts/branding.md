# Branding

Per-tenant identity on one codebase — the site is ONE app wearing many brands, resolved by domain.

- **Resolution is the edge's first job:** host → tenant (apex or subdomain, through the API's domain rules) resolved once in the proxy, stamped into the request — every layout, fetch, and cache key downstream carries the tenant; an unresolvable host serves the platform's landing page, never a broken tenant shell.
- **Branding is a token payload, not a theme fork:** the tenant's brand (palette ramps, radius personality, logo set, font choice from the approved stacks, OG imagery) arrives as data from the API and materializes as CSS variables over the SAME semantic token system — components never know the tenant; a per-tenant component variant is the fork the architecture forbids.
- **The brand payload is versioned and cached hard:** brand changes are rare and tolerant of minutes — cache per tenant with a version stamp in the key; the token injection happens at the layout root server-side so the first paint is branded (a flash of the platform's default theme is a defect the user screenshots).
- **Rendering economics are per-tenant-aware:** catalog/content pages ISR with tags scoped by tenant + entity — one tenant's price update invalidates ITS pages only; the static-params strategy accounts for the tenant dimension deliberately (popular tenants pre-rendered, the long tail on-demand) instead of pretending one site's math applies.
- **SEO is per-tenant infrastructure:** metadata, OG images (brand-templated, generated), sitemaps, and robots resolve per tenant per locale; canonical URLs respect the tenant's chosen domain (apex canonical over subdomain when both exist) — structured data (product/event/course shapes per type) generates from the same type lookup the API serves.
- **Isolation extends to the client side:** cache keys, storage keys, and analytics streams are tenant-scoped; a shared CDN cache never serves tenant A's branded page to tenant B's domain (the tenant is part of every cache identity, including the framework's) — the cross-tenant leak has a frontend edition and it is equally category-one.
- **Feature flags per tenant come from the same payload:** which types the tenant sells, which payment methods, which locales — the site composes its navigation, search facets, and checkout options from tenant capabilities; `if tenant == 'x'` is the same rot as every other literal.
- **The custom-domain lifecycle is visible truth:** a domain mid-verification serves the platform's "almost ready" page with honest status — the provisioning saga's states render, they are never faked as done.
- Preview is a first-class mode: staff preview a tenant's unpublished branding via a signed preview session on the same machinery (draft payload, same tokens) — a parallel "preview site" is a second source of truth nobody maintains.
