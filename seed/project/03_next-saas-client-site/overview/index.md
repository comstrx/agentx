# Index

- **What this is:** the public face of the SaaS core — a Next.js marketplace site where clients browse, search, and book/buy across the platform's types. Per-tenant branded (domain → tenant → theme tokens), SEO-carrying, conversion-obsessed; the only actor here is the client.
- **The journey is the architecture:** discover (home, categories, search with facets) → evaluate (item detail: media, pricing, availability, reviews) → commit (the checkout funnel) → live with it (account: orders/bookings, wallet, reviews, support). Every screen serves one step of that funnel; anything serving none of them is scope creep.
- **Funnels diverge by fulfillment archetype, from one engine:** date-range types check in/out calendars · timed-slot types pick sessions/seats · stock types cart and ship · digital types deliver instantly · gig types collect requirements · enrollment types join courses · application types submit documents. One checkout spine (idempotent placement → payment saga → confirmation on webhook-driven state), archetype-specific steps composed onto it — the client-side mirror of capability-not-type.
- **Rendering economics:** catalog and content pages ISR/static with tag invalidation from the API's events; search and availability live; the checkout dynamic and personal. SEO is structural — server-rendered listings, per-entity metadata/OG, canonical urls, structured data for the types that earn rich results.
- **Booking honesty in the UI:** availability shown from cache, verified live at commit; payment/booking states render the saga truthfully (`processing` is a state, not a spinner that lies); a stuck saga shows "still confirming" with push/poll updates — trust is the conversion feature.
- **The data contract:** the API's collections mirror, the bounded filter DSL for listings/facets, the envelope everywhere; zero business rules client-side — prices, totals, and availability are always the server's word.
- **What "done" means here:** the funnel converts on a mid-range phone — fast (budgets honored), fluid (designed motion), truthful (states honest), findable (SEO structural) — and typecheck/lint/build green.
