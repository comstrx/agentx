# Learning

- **The spine is `course → sections → lessons`, enrollment is the access contract:** content is a tree with ordered units (video, article, quiz, assignment, live session — each a capability, not a lesson subclass); an enrollment row is what grants access — created by purchase, grant, or subscription, carrying its window and state (`active → completed / expired / revoked`).
- **Access control is enrollment + progress, enforced at content delivery:** every content request answers "does this actor hold an active enrollment covering this unit" at the lowest layer — fail closed; free-preview units declare the capability explicitly. Drip/sequential rules (unit N after unit N-1, or after date D) are data on the course, enforced server-side, never client-side gating alone.
- **Media is protected by design:** video and files serve through signed, expiring, actor-bound URLs from private storage — never public buckets, never permanent links that outlive the enrollment; downloads are a per-course capability decision. Piracy cannot be eliminated; hotlinking a whole catalog must be.
- **Progress is an event stream, aggregated:** unit-completed events (with position/score where relevant) append per enrollment; course progress and completion derive from them — recomputable, auditable, feeding certificates and analytics. A mutable `progress_percent` column hand-updated from the player is drift by design.
- **Assessment honestly:** quizzes as data (questions, answers, scoring rules), attempts recorded with timestamps and answers, grading server-side, bounded attempts as policy — a passing score claimed by the client is decoration; certificates issue from verified completion + passing state, carry a verifiable id, and revoke with the enrollment.
- **Cohorts and live sessions are scheduling capabilities:** a course may declare timed intakes (enrollment windows, session calendar) — the timed-slot fulfillment archetype composed onto learning, not a parallel system.
- **Instructor economics ride the marketplace rails:** instructor = vendor; revenue splits, payouts, and refund policies flow through the same ledger + saga machinery — an elearning platform is a marketplace whose items teach.
- Completion, engagement, and drop-off per unit are first-class metrics — the product's health is measured in finished lessons, not sold enrollments.
