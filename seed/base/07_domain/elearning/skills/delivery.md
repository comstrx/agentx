# Delivery

Shipping learning content that is protected, measured, and honest — the craft under the learning contracts.

- **Signed URLs are the content gate in practice:** issuance checks the enrollment + drip rules for THAT unit, binds the URL to the actor, expires it short (minutes for video segments, hours for downloads at most) — the issuance endpoint is the enforcement point; storage is private always, and a leaked URL dies by expiry, not by hope.
- **The video pipeline:** upload → queued transcode to an adaptive ladder (HLS-shaped renditions + thumbnails) → private storage → playback via signed playlist whose segment URLs inherit the binding. Realism about DRM: signing + expiry + actor-binding stops hotlinking and casual sharing — screen capture is not a software problem; price the risk, don't theater it.
- **Progress is throttled events, aggregated honestly:** the player sends position heartbeats throttled client-side; the server records unit events (started, position, completed-on-threshold — e.g. 90% watched) per enrollment; course progress derives by aggregation job — recomputable, auditable, and immune to a client claiming 100%.
- **The quiz engine is data + server truth:** question banks with typed kinds, per-attempt snapshots (the questions served, shuffled order, timestamps), server-side grading against the snapshot, bounded attempts and time windows as policy — the client renders and submits; it never grades, never sees answer keys in payloads, never extends its own timer.
- **Drip enforcement lives at issuance:** sequential and date rules evaluate server-side when content is requested — the UI's locked-lesson display is UX; the signed-URL refusal is the law. A rule change (instructor reorders) re-evaluates naturally because nothing was pre-granted.
- **Certificates are verifiable artifacts:** issued only from verified completion + passing state, carrying a public verification id (a lookup endpoint answers "is this real"), revocable with the enrollment — a PDF without a verification path is decoration, not certification.
- **Cohorts ride the timed-slot machinery:** enrollment windows, session calendars, capacity, waitlists — the same slot/booking rails as any scheduled inventory; live-session attendance is an event on the enrollment like any progress event.
- **Instructor payouts are marketplace rails:** revenue share per enrollment ledgered at capture (net of refund windows), refunds clawing back through the same entries, payout schedules honoring the platform's hold policy — an elearning platform is a marketplace whose items teach; no parallel money system.
- **Anti-abuse with proportion:** concurrent-session caps per enrollment, download-volume anomaly flags, sharing detection by usage shape — enforcement graduated (warn → step-up auth → suspend) and always auditable; punishing paying learners to stop a pirate is a product bug.
- Measure learning as the product: per-unit drop-off, completion rates, quiz failure clusters (a bad question looks like a hard question until the cluster shows), time-to-complete distributions — the instructor's dashboard is these numbers per cohort, fed by the same event stream.
