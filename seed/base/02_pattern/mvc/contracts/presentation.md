# Presentation

- **The domain's shape is never the wire's shape:** every surface (API, panel, export, mail, feed) gets a dedicated presenter/resource/view-model translating outward — the domain changes freely behind stable presentations; a raw model serialized to a client is a contract signed by accident.
- **Presenters shape, never decide:** formatting, field selection, derived display values, link/action assembly — zero business decisions, zero queries, zero side effects. A presenter fetching a relation is a hidden N+1; the data arrives loaded, the presenter arranges it.
- **One envelope per system:** success and failure wear the same uniform shape everywhere (`status`, `data`/`errors`, `message`) — a client learns the envelope once; a second response shape is a second contract to maintain and a client-side `if` forever.
- **Per-actor shaping is capability-driven:** what a vendor sees of an order vs what an admin sees is the SAME presenter reading the actor's permissions — parallel presenter trees per actor (`VendorOrderResource`, `AdminOrderResource`) duplicate drift; fields gate by `can(x)`, not by class explosion. The deliberate exception: surfaces so divergent they are different products (public API vs internal export) — then separate presenters are honest.
- **Null discipline in output:** absent-by-permission, absent-by-type, and genuinely-null are design decisions — hide what the type/actor doesn't have, never leak schema through a swamp of nulls; the payload of a visa never shows `stars`.
- **Collections are presented, not looped:** list output = the item presenter applied by the engine + pagination/meta assembled uniformly — hand-mapping arrays per endpoint is the presentation layer leaking upward into controllers.
- **Localization happens at presentation:** keys resolve to the actor's locale here (messages, labels, formatted dates/money) — the domain speaks keys and canonical values; a hardcoded human string below the presentation layer is a translation bug scheduled.
- **Versioning lives at this layer:** a breaking shape change is a new presenter under a new version prefix — the domain serves both during the migration window; editing the live shape "because it's small" breaks clients you cannot see.
- Test presenters as pure functions: given a loaded model + an actor context → assert the exact payload — cheap, fast, and the contract tests that keep clients unbroken; the presenter suite IS the API's regression net.
