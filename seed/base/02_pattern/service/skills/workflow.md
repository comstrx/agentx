# Workflow

Running use cases that span entities, time, and providers — the service layer's hard craft.

- **The transaction recipe:** open late (after validation and cheap reads), wrap exactly the consistency scope, commit early, fan out after. Events, jobs, mail, and broadcasts dispatch post-commit always — a consequence racing its own uncommitted transaction is the classic heisenbug. Never hold a transaction across an outbound network call.
- **Typed command in, typed result out:** a use case receives a validated shape (the boundary already coerced) and returns a domain result the surface translates — `{ ok, data | failure }`-shaped, never transport types, never half-mutated entities as an error channel.
- **Extract the state machine the moment a lifecycle appears:** enumerate states, legal transitions, and the event each transition emits; route every status change through the ONE transition method with guards — then the use case reads as `order.transition(to: confirmed)` and illegal moves fail loud instead of un-tested. A `status` column written from three services is a corruption generator.
- **Escalate to an explicit workflow when the pipeline outgrows a method:** the signals — steps that must survive a crash, waits on external confirmation, compensation on partial failure. The shape: an intent/workflow row (status, attempts, provider refs, next-retry-at) + queued steps + a scheduled sweeper for stragglers. A method simulating this with nested try/catch is a saga in denial.
- **Compensation is a named step, designed with the flow:** every step that commits before a later step can fail declares its undo (`release`, `void`, `refund`) — executed through the same ports and idempotency machinery, never improvised in a catch block. Steps order so the irreversible happens last.
- **Idempotency at the use-case level:** money-moving and side-effectful use cases run under a key (actor + operation + client key) — replay returns the recorded result; the retry storm becomes safe no-ops. The guard lives once in the platform machinery, declared per use case.
- **Composition without chains:** a use case may call one other use case for genuine composition; a chain of services calling services is a pipeline that lost its owner — extract the shared steps downward into the engine and let ONE service own the story.
- **Concurrency at the contended rows:** lock (or version-check) exactly the rows the invariant needs — wallets, stock, seats — held for the shortest scope, acquired in consistent order across use cases. Optimistic where contention is rare, pessimistic where money moves.
- **Time is an input:** deadlines, grace windows, and expiries are data evaluated against an injected clock — scheduled sweepers make time-driven transitions (expire, remind, reconcile) explicit jobs, never side effects hidden in unrelated reads.
- **Test the use case as a table:** given state → run → assert new state + emitted events + written entries; then the pathological rows — duplicate call under one key, crash between steps (sweeper resolves), compensation path, illegal transition refused. The happy path is one row of many.
