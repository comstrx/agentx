# Security

Hardening the server surface — the craft that assumes the request is an attack until proven a customer.

- **Token lifecycle done right:** short-lived access tokens + rotating refresh tokens (one-time-use: a replayed refresh token revokes the family — stolen-token detection built into the protocol); revocation is instant-effective (a deny-list/version check on the hot path, cached with revocation-keyed invalidation); logout means revoked, not just forgotten client-side.
- **Credential endpoints are a fortress of their own:** login/OTP/reset throttled by actor AND source (fail-closed), constant-time comparisons, no user-enumeration oracles (same answer for wrong-user and wrong-password, same timing), password hashing by the current-generation algorithm with tuned cost — and every credential event (login, fail, reset, new device) lands in the audit trail.
- **Secrets have one home and it is not the repo:** environment/secret-manager injection, read once at boot into typed config, never logged (the redactor knows the key patterns), never in error payloads, rotated on a schedule that has been REHEARSED — a rotation that has never been executed is a secret with tenure.
- **Injection defense is structural, per sink:** parameterized queries (the ORM's default, verified at review for every raw fragment) · shell exec through arg arrays never string interpolation · path traversal killed by resolving against a jailed base · template injection impossible by never templating user input as code — each sink class has its one guarded door.
- **SSRF guard on every outbound URL a user can influence:** scheme whitelist, DNS-resolved IP checked against private/link-local/metadata ranges (and re-checked on redirects), tight timeouts, response size caps — webhook destinations, avatar fetchers, and "import from URL" features are the classic doors.
- **Uploads are hostile bytes:** size caps before buffering, content-type verified by sniffing not extension, images re-encoded (strips polyglots + EXIF), stored under generated keys in private storage, served with content-disposition + a no-execution domain — an upload path that trusts filenames has already been owned somewhere.
- **Headers and transport as baseline:** TLS everywhere, HSTS, strict CORS (explicit origins, never `*` with credentials), security headers set once at the edge middleware — and cookies (where used) `httpOnly`+`secure`+`sameSite` by default.
- **Dependency and image hygiene on a rhythm:** lockfile audit in CI (fail on known-critical), base images minimal + rebuilt on schedule, no dev tooling in production images — the supply chain is attack surface with a package manager.
- **Abuse visibility is a detection system:** auth failures, permission denials, limiter trips, webhook signature failures — logged with source fingerprints, aggregated, and alerting on pattern (the slow enumeration, the credential-stuffing wave) — refusals that nobody watches are reconnaissance succeeding quietly.
- Drill the incident before it happens: token-leak runbook (rotate, revoke family, audit trail sweep), dependency-CVE runbook (assess exposure, patch, verify), and a tabletop walk of each — the security posture is what the team can EXECUTE at 3 AM, not what the checklist says.
