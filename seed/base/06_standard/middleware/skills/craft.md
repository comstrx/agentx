# Craft

Building pipeline units that are cheap, honest, and composable — the engineering behind the edge law.

- **A unit's anatomy:** state its assumption (what already ran) and its guarantee (what is now true) at design time; do one job; refuse with the uniform envelope + correct status; pass on. The assume/guarantee pair is the pipeline's type system — reordering that breaks a pair is caught in review because the pair is written down.
- **Context stamping done right:** resolve identity/tenant/locale ONCE, write through the single context accessor, and register the symmetric reset (request end, exception path, worker recycle) in the same unit — the stamp and the reset are one feature; long-lived workers turn a missing reset into a cross-actor leak.
- **Authentication stays cheap by caching the verdict, not the check:** token → actor resolution cached with a short TTL and revocation-keyed invalidation (a revoked token dies now, not at TTL) — the auth store is on every request's path; its latency is everyone's latency.
- **The idempotency unit is a replay cache with a lock:** an explicit `Idempotency-Key` stores the response ~24h; unkeyed mutations get a short body-fingerprint grace window (seconds) against double-submits; a concurrent duplicate hits the in-flight lock and refuses as a CONFLICT ("already in flight") — the loser never executes twice; replays return the stored response verbatim plus a replay header; only sub-500 responses are stored (a 500 must stay retryable); GET/HEAD and keyless file uploads pass through. The key scopes by tenant|actor|method|path — one actor's key never replays another's response.
- **Gates are parameterized, resolution is central:** `has:{permission}`, `throttle:{class}`, `plan:{feature}` — the route declares the parameter; the gate resolves through the same permission/plan machinery as everything else. A gate embedding its own resolution logic is a second authorization system growing in the dark.
- **Order-dependence is tested as behaviour:** the suite asserts the contract chain — unauthenticated → 401 before any budget is spent; unresolvable tenant → refusal before the body parses; a throttled actor's refusal costs one store hit, not a walk through the whole pipeline. The cheap-and-fatal gates run first by design.
- **Symmetry on the way out is where the bugs hide:** timers stopped, locks released, context reset, response headers stamped — on success AND on every failure path; a unit that alters state only on the happy path is a leak generator under load.
- **The exception translator is the outermost ring and the only author of error responses:** domain error → machine key + status + envelope in one mapping table; a handler or inner unit crafting an error response by hand is a second contract drifting from the first.
- **Measure the pipeline as a budget:** per-unit timing visible in dev traces, the pipeline's total on the hot-path dashboard — middleware runs on EVERY request; a 5ms unit is a 5ms tax on the whole product, and the tax table is reviewed like any hot path.
- **Composition is declared per surface, once:** each route group (panel, public API, webhooks) declares its named stack; a new route attaches to a group and inherits the right pipeline — hand-assembling middleware per route is how one route ships without auth.
- Test units in isolation with fake context, then the assembled stack against the real routes — the unit test proves the job; the stack test proves the order; production needs both proofs.
