# Channels

Designing and operating the realtime surface — channels, presence, reconnection, and scale.

- **Channel taxonomy with scope in the name:** `tenant.{id}.user.{id}` (private per-actor), `tenant.{id}.order.{id}` (entity watchers), `tenant.{id}.presence.{room}` — the scope prefix makes cross-tenant subscription unrepresentable and lets the auth layer authorize by pattern, not by list.
- **The subscription handshake is an authorization endpoint:** client requests a channel → server verifies with the SAME permission machinery as HTTP (actor, tenant agreement, entity access) → signed grant. A channel authorized once at connect is re-verified on sensitive scopes when the grant ages — revocation must mean something.
- **Reconnect + catch-up is the core loop, designed first:** the client tracks a last-seen cursor (event id/timestamp per subscription); on reconnect — resubscribe, then a catch-up read through the normal API since the cursor, then merge deduped by event id. The socket accelerates, the API guarantees; a client trusting the socket buffer for missed events has a data-loss architecture.
- **Reconnect storms are engineered away:** exponential backoff with jitter on the client, connection-rate shedding at the edge — a deploy disconnecting 50k clients who all retry at t+1s is a self-inflicted DDoS; the jitter is not optional politeness.
- **Presence is ephemeral machinery:** TTL'd heartbeats in the broker's transient store; join/leave derive from key expiry, not from clients promising to say goodbye; the database is never a heartbeat monitor. Presence payloads carry identity only — profiles hydrate through the API.
- **Fan-out economics:** one publish per event, the broker fans out — the app never loops over connections. Tenant-wide or platform-wide announcements go through a queued fan-out that chunks by channel shard; a synchronous 100k-channel publish inside a request is an outage button.
- **The client is a state machine:** connecting → connected → degraded → offline, with the UI honest about it — degraded mode falls back to polling the API on a slow interval; features declare whether they require live (chat) or merely enjoy it (counters), and degrade accordingly.
- **Payload discipline under fan-out pressure:** deltas + ids, hydrate on demand; a fat payload multiplied by fan-out is the bandwidth bill and the broker's latency both. Private data never rides a shared channel — the channel's audience defines the payload's ceiling.
- **Scale is topology:** socket nodes stateless (subscriptions live in the broker's pub/sub), added horizontally, drained gracefully on deploy (close with a reconnect hint, let backoff spread the herd); the only sticky thing is the TCP connection itself.
- Load-test the shapes that kill: connection avalanche after deploy, hot-channel fan-out (one order watched by thousands), slow-consumer backpressure (the broker's policy for a client that cannot keep up is chosen, not discovered) — dashboards on connections, fan-out sizes, delivery latency, auth refusals.
