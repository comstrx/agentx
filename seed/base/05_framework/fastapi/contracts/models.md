# Models

- **Pydantic v2 is the boundary, and the boundary is total:** every byte entering (bodies, query shapes, env, provider payloads, queue messages) and leaving (responses) passes through a model — a raw `dict` crossing a layer is an unvalidated claim wearing a type hint.
- **Split the shapes honestly, always three at minimum:** `XCreate` (what a client may send), `XUpdate` (all-optional, only the mutable), `XOut` (what leaves — and nothing more). One god-model reused for input and output leaks columns in both directions: mass assignment inward, data exposure outward; the split IS the security control.
- **Constraints live in the field, not the endpoint:** lengths, ranges, patterns, enums via `Field`/`Annotated` types — the model rejects garbage before any code runs; a manual `if len(x) > 120` inside an endpoint is validation that the next endpoint will forget.
- **Validators normalize, the interior trusts:** `field_validator` trims/coerces/canonicalizes at the edge (the cast layer's job — phone formats, casing, empty-to-none), `model_validator` holds cross-field rules (end > start) — after the model, the pipeline never re-checks; re-validation deep in a service means the boundary leaked.
- **Strictness is chosen per model, deliberately:** boundary models lean strict (`model_config` strict where coercion would hide client bugs); internal shapes may coerce — the default is never "whatever v2 does"; it is a written decision on the model.
- **`response_model` on every route, with output filtering as the point:** the Out model whitelists what leaves — extra ORM attributes, lazy relations, and internal fields die at serialization; `from_attributes` bridges ORM objects without letting them BE the contract.
- **Reused vocabularies are `Annotated` types, defined once:** `TenantId`, `Money` (minor-units int), `Slug`, `Locale` — constraint + serialization behavior travel with the type; twenty fields re-declaring the same regex are twenty chances to drift.
- **Enums are the closed sets, shared with the domain:** the same `StrEnum` the domain logic branches on serializes at the boundary — a string field with a documented list of values is an enum that forgot to exist.
- **Computed fields shape output, never hide work:** `computed_field` for cheap derivations (display names, flags) — anything touching IO or a relation belongs in the pipeline before serialization; a serializer doing queries is the N+1's favorite costume.
- **Versioned payload evolution follows the additive law:** new optional fields freely; renames/retypes are a new model version behind a new route version — consumers parse with `extra="ignore"` tolerance, and the OpenAPI diff in CI is the breaking-change tripwire.
- The generated OpenAPI is the contract of record: schemas, examples (`json_schema_extra`), and tags maintained as code — if the docs read wrong, the models ARE wrong; fixing the doc means fixing the type.
