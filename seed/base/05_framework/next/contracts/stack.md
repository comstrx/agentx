# Stack

- **Never assume versions or API shape from memory — `package.json` + the lockfile win** over anything you think you know. Read them first; the framework moves fast and half of trained knowledge is one major behind.
- The house floor: **latest major Next (App Router) + latest major React** — Server Components, server actions, streaming, and the async request APIs are the baseline vocabulary, not advanced features. TypeScript strict, Tailwind on tokens, the project's chosen motion/query/validation libraries — and nothing duplicating them.
- **Know the current framework's sharp edges before writing:** fetch is uncached by default (opt into caching explicitly); `params`/`searchParams`/`cookies`/`headers` are async — await them; the edge entry file and bundler defaults follow the installed major, not memory (the current era: Turbopack is the bundler, the edge entry is `proxy.ts`). When the installed version disagrees with your training, **the installed version is right** — check the migration notes in the repo or lockfile era.
- **The current-era toolchain, when the repo declares it — verify, then obey absolutely:** React Compiler on (`reactCompiler: true`, never remove — hand memoization becomes the exception) · Tailwind v4 CSS-first (tokens/theme live in `globals.css` `@theme`; there is NO `tailwind.config.*` — never create one) · Biome for lint + import order with the formatter deliberately retired (the hand-style law — never re-enable it) · one package manager, the one the lockfile names, never a second.
- **Dependency discipline:** the framework + React cover routing, data flow, caching, and rendering — a library is added only for what they genuinely do not do (complex client tables, charts, advanced motion), and each one arrives behind a house wrapper so a swap stays a one-file change. No jQuery-era utilities, no two libraries for one job, no state library because a tutorial used it.
- **Env and secrets:** server env stays server-side; only `NEXT_PUBLIC_*` reaches the client and each such exposure is a reviewed decision. Runtime config comes from the environment, never hardcoded per deploy target.
- **The gate:** typecheck + lint green with zero suppression, and a production build (`next build`) — build success is part of every change's definition of done; a change that only works in dev is not done.
- Deployment assumptions stay portable: standalone output, no vendor-locked APIs without a wrapper, images/fonts through the framework pipeline so the CDN story survives a platform move.
