# Testing

The gate's second half — a suite that proves the engine, the tenancy, and the money.

- **Pest/PHPUnit through the HTTP surface first:** feature tests hit real routes with real middleware (auth, tenant resolution, permission gates) and assert the envelope — a test bypassing the boundary proves code that no request will ever run; unit tests are reserved for Support-domain purity and hairy pipeline steps.
- **The two-tenant fixture is the suite's spine:** the base test case seeds TWO tenants + actors per role; every resource's tests assert the other tenant sees nothing (list empty, show 404, update refused) — the isolation test failing is a category-one release blocker, and it is one inherited assertion, not per-test heroics.
- **Database strategy that matches Octane reality:** transaction-wrapped tests for speed, against the same engine as production (Postgres in CI — RLS, `NULLS NOT DISTINCT`, and partial indexes do not exist in sqlite; a suite green on sqlite proves a database nobody deploys); the RLS probe test connects as the app role and proves the policy bites.
- **Factories mirror the engine's laws:** UUIDv7 ids, `tenant_id` stamped from the fixture's current tenant, states for the domain's real shapes (`confirmed()`, `expired()`, per-type item states) — a factory hand-crafting what boot hooks stamp in production is testing a parallel universe.
- **Permission tests are table-driven:** one test per resource walks the verbs × roles matrix from the SAME source that declares them (the derived `view_/add_/edit_/delete_` quartet + cross-cutting flags) — asserting granted passes and missing denies; adding a permission without its matrix row fails the suite, which is the point.
- **Money and lifecycle tests replay the ugly sequences:** duplicate webhook, out-of-order capture-before-auth, idempotency-key replay on placement, balance race (two parallel debits, one lock) — table-driven over the state machine; the happy path is one row. `Event::fake`/`Queue::fake` assert the consequences fired; a paired test runs the REAL job path for the saga's spine.
- **Time and randomness are controlled inputs:** the clock through the Date support domain (test sets it), sweeps and expiries tested by time-travel not sleeps — a test with `sleep()` is a flake with a schedule.
- **Static analysis is half the gate:** Larastan at max level, zero suppression, in CI beside the suite — the suite proves behavior, the analyzer proves the types didn't lie about it; both green = done, either red = not done.
- **Coverage follows the risk map, not the percentage:** tenancy isolation, permission matrix, money movements, state machines, the engine's derivation (relations map, filter DSL guards) — exhaustively; CRUD declarations that are pure engine pass-through get the smoke test the engine already earned. A coverage number chased for its own sake produces tests that assert nothing.
- The suite is fast or it is skipped by humans: parallel execution, transaction rollbacks, no real network (fake the ports; the drivers get their own sandbox-matrix runs) — a ten-minute suite becomes optional by Thursday; keep the feedback loop under the coffee refill.
