# Concurrency

Tokio-era concurrency inside actix — correct first, fast by measurement.

- **The shared-state ladder, lowest rung wins:** immutable `Data<T>` (config, pools, clients) → `Data<RwLock<T>>` for rarely-written state with instant reads → a dedicated task owning the state behind an mpsc channel (actor-shaped) when writes contend or ordering matters. Reaching for a `Mutex` around something hot is a design smell before it is a performance bug.
- **Never block a worker:** CPU-heavy work (hashing, compression, image/media, big serialization) and sync-only IO go through `web::block`/`spawn_blocking` — the blocking pool is bounded, so cap concurrent heavy jobs with a semaphore; an unbounded fan of blocking tasks just moves the stall. Async file IO libraries lie less than they used to — measure before trusting either path.
- **Every await has a deadline:** outbound HTTP, database acquire + query, cache, locks — wrapped in `tokio::time::timeout` or the client's own timeout config; the budget topology holds client-call < handler < proxy so the caller always learns the truth from the layer that knows it.
- **Cancellation safety is a review axis:** a handler future can be dropped at ANY await (client disconnected) — work that must complete regardless (ledger writes, provider calls mid-saga) is spawned to a supervised task or queued, never left inline hoping the request survives. State mutated before an await is either transactional or restored on drop.
- **Background work is supervised, never detached:** long-lived tasks (consumers, sweepers, refreshers) spawn at composition with a shutdown signal (watch/broadcast channel), are joined on graceful shutdown, and restart with backoff on panic — a silently-dead detached task is an outage with no symptom.
- **Backpressure by bounded channels:** every internal queue has a capacity and a decision for "full" (await, shed, error) — `unbounded_channel` is a memory leak with a rationale; semaphores gate the expensive sections (exports, provider fan-outs) so a burst queues at the boundary instead of exhausting pools.
- **Pool math done once:** connections = workers × expected concurrent acquires, bounded by what the database actually serves across replicas; `acquire_timeout` set so exhaustion is a fast clear error; acquire late, drop early — a connection held across an outbound call is pool theft.
- **Fan out deliberately:** independent awaits join via `try_join!`/`join!`; homogeneous fans use buffered streams (`buffer_unordered(n)`) with a chosen concurrency — an unbounded `join_all` against a provider is a self-inflicted rate-limit incident.
- **Locks across awaits are forbidden by default:** a std `Mutex` guard held over an await can deadlock the runtime; use async-aware locks when holding is unavoidable, restructure so it is rarely unavoidable — compute, then lock briefly, then release.
- **Test concurrency with the runtime's tools:** `tokio::time::pause` for time-travel over backoff/expiry logic, deterministic seeds for jitter, tests that race duplicate requests under one idempotency key — the suite proves the guards, not the happy path.
- Measure with the runtime visible: tokio-console/metrics for stalled tasks and blocked workers, flamegraphs for CPU, pool gauges for saturation — latency mysteries are almost always a blocking call or pool starvation wearing a costume.
