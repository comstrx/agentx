# Errors

- **One `AppError` enum is the service's whole error vocabulary:** every fallible path returns `Result<T, AppError>`; variants model the THREE families distinctly — validation (rejected input), refusal (domain said no: named, stable keys), failure (the world broke: db, provider, timeout) — a handler or service inventing a second error type has forked the contract.
- **`ResponseError` is implemented ONCE, and it is the envelope factory:** `status_code()` maps variant → status (422 validation / 403-404-409 refusals by kind / 500-502-504 failures), `error_response()` renders the uniform envelope (`status`, machine `key`, localized-ready `message`, `errors` map for fields) — no handler ever constructs an error response by hand; the mapping table in this one impl IS the API's failure contract.
- **Refusal keys are stable API:** `insufficient_balance`, `hold_expired`, `permission_denied` — matched by clients, documented in the contract mirror, never renamed casually; the human message may change freely, the key is forever.
- **Failures redact outward, log inward:** the 5xx envelope says retryable-or-not and nothing else; the full story (source error chain, query, provider payload) logs once at the translation point under the correlation id — `#[from]` conversions preserve the chain (`thiserror`-shaped), the display text of internal variants never reaches a client.
- **Extractor rejections join the same contract:** JSON deserialization, path/query type failures, and validation-layer rejections are configured (custom error handlers on the extractor config) to render the SAME envelope — the default plain-text 400 is a second contract shipped by omission.
- **`From` implementations do the boundary translation:** `sqlx::Error → AppError` (unique-violation → the named refusal it means, not a 500), `reqwest`/provider errors → classified failure variants (transient/rejected/down) at the port — services write `?` and stay clean; classification happens once per source, at the conversion.
- **Panics are infrastructure failures, not flow:** `unwrap`/`expect` banned on request paths (the house law); a panic that does occur is caught by the runtime, answers a generic 500 envelope, and pages someone — but the design goal is that the panic path is unreachable, proven by the same `Result` discipline as everywhere.
- **Not-found is fail-closed and uniform:** unknown routes, unknown ids, and ids outside the actor's scope all answer the SAME 404 shape — a scope-denied 403 vs 404 difference is an existence oracle leaking tenant data one status code at a time.
- Refusals are values in tests: table-driven tests match on the variant (and its rendered key + status) — asserting on message strings welds tests to copy; asserting on variants welds them to the contract, which is the weld you want.
