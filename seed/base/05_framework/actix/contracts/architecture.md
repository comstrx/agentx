# Architecture

- **Handlers are the controller law in Rust:** an actix handler extracts typed input, calls one service entry point, returns a typed response — five lines. Business logic, query building, or native munging inside a handler is misplaced code; the layered pattern (support → repository → service → handler) applies unchanged.
- **Extractors are the boundary:** `Json<T>`, `Path<T>`, `Query<T>` deserialize into validated, typed shapes — validation happens in the extractor layer (derive validators or a custom `FromRequest`), never re-checked downstream. A handler taking raw `HttpRequest` to fish values manually is a boundary leak.
- **State is `Data<T>` and immutable by design:** shared services, pools, and config wrapped once at composition (`App::new().app_data(...)`); anything mutable inside is behind its own guard with a named reason. Per-request state travels in request extensions set by middleware — never in statics; the workers are long-lived and concurrent.
- **Errors are one domain type implementing `ResponseError`:** services return `Result<T, AppError>`; the error type maps variants to status codes + the uniform envelope in ONE place. `unwrap` in a handler is a 500 with no story — banned as everywhere.
- **Middleware carries the cross-cutting:** auth, actor/tenant context, correlation id, throttling — declared on scopes, feeding typed context into extensions; handlers read context through one accessor, never re-parse headers.
- **Routes are declared in composable scope functions** (`fn products () -> Scope`), grouped per resource/panel, mounted at the composition root — mirroring the reusable-route-block law; handler registration stays greppable, never macro-scattered beyond the standard attributes.
- **Async discipline is load-bearing:** never block a worker — CPU-heavy or blocking IO goes through `web::block`/spawn_blocking; every outbound call has a timeout; connection pools are sized deliberately and shared through `Data`.
- The binary stays a thin shell over a library crate — handlers, services, and support are library code, testable without HTTP; the `main` wires config, pools, and the server. Same library-first law as every Rust deliverable.
