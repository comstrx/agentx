# Performance

Re-render engineering — measured, structural, and honest about what the compiler now does for free.

- **The profiler is the only prosecutor:** React DevTools profiler (why did this render, what did it cost) before ANY memoization — decorative `useMemo`/`useCallback` sprinkled by anxiety is noise that hides the real storms; a memo without a measured render problem is a comment that lies about performance.
- **The React Compiler changes the default:** where enabled, it memoizes components and values automatically — hand memoization becomes the EXCEPTION (escape hatches, library boundaries the compiler cannot see through), and the skill shifts to writing compiler-legal code: pure render paths, no mutation during render, rules-of-react compliance the compiler can verify.
- **Structure beats memoization anyway:** push state DOWN (a ticking value in a leaf cannot repaint a tree) · lift CONTENT up (`children` passed through a stateful wrapper do not re-render with it) · split providers (state and dispatch in separate contexts; fast-changing values out of context entirely) — the composition patterns that make memo unnecessary outlive every memo.
- **Lists are the hot path, always:** stable keys from domain ids · rows memoized with primitive/stable props (the one habitual memo even with the compiler) · virtualization past the threshold (windowed rendering for tables/feeds) · pagination by cursor with prefetch — a 1000-row map without virtualization is the classic self-inflicted jank.
- **Transitions separate urgent from ambient:** `useTransition` for navigation/filter changes that may lag (typing stays instant, results catch up), `useDeferredValue` for the expensive derived view of a fast-changing input — the UI's responsiveness budget spent deliberately instead of blocking on every keystroke.
- **Effects are a performance surface too:** an effect chain (state → effect → state → effect) is a render cascade — derive instead of syncing; subscriptions go through `useSyncExternalStore` with narrow selectors so an external store tick repaints subscribers, not the app.
- **Measure INP, not vibes:** slow interactions decompose into input delay (main thread busy — chunk the work), processing (the handler itself — defer the non-visual), and presentation (layout thrash — batch reads/writes); long tasks break up with transitions/idle scheduling.
- **Expensive children mount once:** modals/editors/charts lazy-load at the interaction that needs them (`lazy` + Suspense), heavy libraries stay out of the initial graph, and conditional mounting beats CSS-hiding for anything with subscriptions.
- **Identity discipline at boundaries:** new object/array/closure props defeat every memo below them — hoist constants, derive with stable references, keep context values memoized; the profiler's "props changed: style" pointing at an inline object is the signature to hunt.
- The regression net: a profiler pass on the money screens per release + render-count assertions on the known-hot components — performance decays by a thousand innocent diffs; the net catches the one that tipped it.
